## Specs

- S1. Acceptance criteria of #3, verbatim: "A gentle-pi session can speak through Socra and receive dictated input." / "Behavior without Socra running is unchanged." This work takes the option the issue lists as an open question, "Socra launching Pi as its agent backend": Socra starts Pi, sends it the dictated turns and speaks its replies. Pi's own configuration is never modified, so Pi without Socra behaves as before.
- S2. Second adapter behind the existing port (agent-mode S1: "the port and its events carry no Claude Code names"): `server/src/socra_server/adapters/pi_agent.py` implements `AgentBackend` / `AgentConversation` with a backend id and label, a model list from Pi's configured providers (at least the default), `check()` returning ready / not_configured / unreachable with a clear message, reply events mapped to the existing domain events, and interrupt. No change to `ports.py` or `domain/agent.py`.
- S3. Permissions: Pi has no per-tool approval of its own ("it does not ask for approval before every tool call", Pi `docs/security.md`). Extensions such as gentle-pi ask through `confirm` dialogs; in RPC mode those reach the caller and are mapped to the `PermissionDecider` (allow only on an explicit `True`; no answer or a failure is a denial). Pi otherwise runs with its own settings (gentle-pi permission mode Normal / Auto / YOLO), as Claude Code runs with the user's `defaultMode`.
- S4. Registry: `agent_backends` lists both Claude Code and Pi.
- S5. Scope limits from the task: no change to `web/src` (another session is redesigning it; the page renders any backend the server lists) and no change to exam mode.
- S6. Provider use (L10): "Use only the Antigravity subscription for any Pi call, never openai-codex" and "do not make the adapter default to openai-codex; list the configured providers' models and let the user choose, and for the smoke run use antigravity/gemini-3.8-flash." The model list keeps Pi's order without preferring Pi's default provider, includes extension providers (Antigravity), and every session starts with an explicit `--provider`/`--model`.

## Findings: driving Pi from Python (installed Pi 1.3.0, `@earendil-works/pi-coding-agent`)

Evidence: `pi --help`; package docs under `~/.pi/agent/install/releases/1.3.0/node_modules/@earendil-works/pi-coding-agent/docs/` (`rpc.md`, `rpc-commands.md`, `json.md`, `rpc-extension-ui.md`, `security.md`); gentle-pi 4.3.0 sources and `docs/permission-modes.md`; real probes in a scratch folder (L3-L6).

| Need | How Pi does it |
|---|---|
| Programmatic mode | `pi --mode rpc`: long-lived child process, JSONL commands on stdin, `response` records and session events on stdout, diagnostics on stderr. Split records on LF only. Closing stdin is the orderly shutdown. |
| Provider / model | `--model <provider>/<id>` at start, or the `set_model` command. An unknown model makes Pi exit with code 1 and `Error: Model "..." not found` on stderr. |
| Working folder | The process working directory (`cwd` of the child). Project-local resources (`.pi/...`) load only with saved trust; RPC cannot show the trust prompt, so with the default `ask` they are skipped. |
| Model discovery | `get_available_models` returns only models whose provider has credentials (anthropic, not logged in, is absent); `get_state` returns the default model. With `--no-extensions --no-skills --no-mcp --offline` this takes ~1.2 s; with the user's extensions ~12 s, and extension providers (antigravity) appear only then. |
| Login state | `pi auth check --provider <p> --json --no-refresh` prints `{"status":"ready"}` or `{"status":"not_ready","reason":"credentials_not_configured"}` (~1 s). |
| Send a turn | `{"type":"prompt","message":...}`; the response's `data.disposition` is `started`, `queued` or `handled` (no run). |
| Stream text and tools | `message_end` carries each final message; assistant messages hold `text` and `toolCall` blocks and `stopReason` (`stop`, `toolUse`, `error`, `aborted`, ...) with `errorMessage`. `tool_execution_start` carries `toolName` and `args`. `message_update` deltas are per token (not used: the page adds one timeline entry per `agent_text`). |
| End of a turn | `agent_settled` (`aborted` true after an abort). `agent_end` alone is not the end: retries and follow-ups can continue. |
| Interrupt | `{"type":"abort"}`; observed: the running bash tool ends with "Command aborted", then `agent_settled {"aborted":true}`. |
| Permissions | No built-in approval. Extension dialogs (`confirm`, `select`, `input`, `editor`) arrive as `extension_ui_request` and block until an `extension_ui_response` with the same id. gentle-pi's guarded commands use `confirm` (title "Allow recognized data-loss command?", message = the command). `notify`, `setStatus`, `setWidget`, `setTitle`, `set_editor_text` are fire-and-forget. |
